# RC 2 图传回归验证

运行环境：Minecraft 1.20.1、Fabric、Java 17、原版渲染器。

## 运行

`src/renderQa` 是独立的开发测试模组，不打包到发布 JAR。

1. 将一个可进入的测试存档复制到 `run-render-qa/saves/Feed Render QA`。
   本次使用 `run/saves/RC2 Mouse QA` 的副本，原存档未修改。
2. 执行 `./dev.ps1 runRenderQa --console plain --max-workers=4`。
3. 客户端自动进入副本，在原点建立棋盘地面、牛和信号设备，配对遥控器并采集截图。
   测试会修改副本中的场景，结束后自动保存并退出。
4. 查看 `run-render-qa/screenshots` 和日志中的 `RENDER_QA` 行。

## 场景与验收

- `01-low`：对地 5 格，验证九个位置的牛和地面、信号柱与基站的位置关系。
- `02-medium`：对地 40 格。
- `03-high`：对地 100 格，俯视地形。
- `04-above-world`：对地 400 格，超过此平坦世界的建造高度，确认无人机仍存在且地面可见。
- `05-high-horizon`：对地 100 格、水平视角，确认地平线无黑带。
- `06-resized`：飞行界面中将窗口改为 1100×700，确认图传缓冲区跟随尺寸变化。
- `07-normal-view`：退出遥控器后恢复玩家视角。
- 每个飞行场景保存原始 `-feed.png` 和遥控器界面 `-screen.png`，两者均需检查。
- 服务端断言新放置基站和信号柱的 `hasBlockEntity()` 为 false、`getBlockEntity()` 为 null。

## 已定位的原因

1. 固定 960×540 图传缓冲区与原版按窗口大小建立的中间缓冲区不匹配，
   中间缓冲区清空后改变视口，导致地形和实体投影尺度不同。
2. 原版世界背景清空时 alpha 为 0，GUI 纹理着色器会丢弃这部分像素，露出黑底。
   现在在图传完成后只将 alpha 归一为 1，不修改画面 RGB。
3. 同帧两次世界渲染共享异步地形遍历缓存；现在飞行界面只执行无人机视角世界渲染，
   并把原版依赖玩家坐标的地形中心与天空高度改为无人机相机坐标。
4. 原版生物远距离消失逻辑也适用于无人机基类；无人机现在禁用自然消失。

旧存档中原有信号柱的空方块实体数据会被 Minecraft 忽略并在保存后清除，方块 ID 保留。
本验证针对原版渲染路径，未覆盖第三方着色器或其他渲染优化模组。
